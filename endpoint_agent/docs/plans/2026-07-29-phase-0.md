# ShieldDome Endpoint Agent Phase 0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` for inline execution, then apply `tdd` to every behavior slice and `verification-before-completion` for the final gate. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish only the independent Endpoint Agent Python scaffold, immutable initial domain contracts, repository hygiene, and executable offline constraints required by Phase 0.

**Architecture:** Keep every production artifact under `endpoint_agent/src/shielddome_endpoint/` and every guard under `endpoint_agent/tests/`. The production package contains only version metadata and passive immutable data types; capability and repository guards inspect source, dependency declarations, and ignore behavior without opening a network connection or implementing runtime services.

**Tech Stack:** Python 3.12, standard-library `dataclasses`, `datetime`, `ast`, `tomllib`, `subprocess`, `unittest`, and the project-local PEP 517 wheel backend; Git `check-ignore`.

## Global Constraints

- Modify or create files only below `endpoint_agent/`; preserve all pre-existing user changes.
- Use the existing working tree and branch. Do not create a worktree or branch, and do not commit, push, or open a pull request.
- Keep the Endpoint Agent fully offline: no network client, server, socket, listening port, external model, telemetry, or updater dependency.
- Do not implement mail parsing, model loading/inference/training, Native Messaging, database behavior, encryption, UI, adapters, attachment processing, or any later-stage placeholder.
- Use Python 3.12 and standard-library `unittest`; do not add pytest.
- Keep original email and attachment content out of persisted artifacts. Phase 0 creates no persistence behavior.
- The package is per-user product scaffolding only; Phase 0 creates no shared service or central-backend integration.
- The required full test command is `python -m unittest discover -s endpoint_agent/tests -v` using the bundled Python 3.12 runtime when `python` is not present on PATH.
- Replace the Phase 0 status with `complete` only after the pre-status verification gate succeeds; rerun the full test command and Git checks after that single status edit.

## File Map

- `endpoint_agent/pyproject.toml`: minimal PEP 517 build metadata, Python 3.12 floor, and an empty runtime dependency list.
- `endpoint_agent/_build_backend.py`: zero-external-dependency PEP 517 backend that packages the Phase 0 Python source into a pure-Python wheel.
- `endpoint_agent/.gitignore`: Endpoint Agent-specific exclusions for model artifacts, training data, keys, logs, SQLite files, diagnostics, caches, and build outputs.
- `endpoint_agent/src/shielddome_endpoint/__init__.py`: package version plus root-level re-exports of the four public domain types and schema-version constants.
- `endpoint_agent/src/shielddome_endpoint/domain.py`: immutable Phase 0 definitions of `MailObservation`, `FeatureVector`, `ModelAssessment`, and `DetectionOutcome`; no services or processing logic.
- `endpoint_agent/tests/test_package.py`: package import and public-export seam.
- `endpoint_agent/tests/test_domain.py`: public fields, construction, version fields, and immutability at the domain seam.
- `endpoint_agent/tests/_offline_guard.py`: test-only static inspection helper for production Python imports, URL literals, and runtime dependency declarations.
- `endpoint_agent/tests/test_offline_constraints.py`: proves the guard detects forbidden capability and applies it only to production source/dependencies.
- `endpoint_agent/tests/test_repository_hygiene.py`: invokes `git check-ignore` against representative Endpoint Agent runtime artifacts without creating those artifacts.
- `endpoint_agent/docs/plans/2026-07-29-phase-0.md`: this Phase 0 execution record.
- `endpoint_agent/DEVELOPMENT_PLAN.md`: receives only the final `Status: pending` to `Status: complete` change after all earlier gates pass.

`shielddome_endpoint` exports:

```python
__version__: str = "0.1.0"
MAIL_OBSERVATION_SCHEMA_VERSION: str = "1.0"
```

`shielddome_endpoint.domain` defines frozen, slotted dataclasses with immutable tuple-based collection fields:

```python
@dataclass(frozen=True, slots=True)
class MailObservation:
    source_kind: str
    source_message_id: str
    subject: str
    sender: str
    reply_to: str | None
    recipient_summary: tuple[str, ...]
    sanitized_body_text: str
    authentication_observations: tuple[tuple[str, str], ...]
    normalized_links: tuple[str, ...]
    attachment_metadata: tuple[tuple[str, str], ...]
    language_hint: str | None
    observed_at: datetime
    schema_version: str = MAIL_OBSERVATION_SCHEMA_VERSION

@dataclass(frozen=True, slots=True)
class FeatureVector:
    numeric_features: tuple[tuple[str, float], ...]
    categorical_features: tuple[tuple[str, str], ...]
    text_input: str | None
    text_vector: tuple[float, ...] | None
    missing_value_mask: tuple[str, ...]
    schema_version: str = FEATURE_SCHEMA_VERSION

@dataclass(frozen=True, slots=True)
class ModelAssessment:
    probability: float
    confidence_state: str
    execution_status: str
    model_version: str
    feature_schema_version: str
    duration_ms: int
    error_code: str | None = None

@dataclass(frozen=True, slots=True)
class DetectionOutcome:
    local_event_id: str
    final_risk_score: int
    risk_level: str
    generic_action: str
    execution_state: str
    structured_private_evidence: tuple[tuple[str, str], ...]
    minimal_plugin_projection: tuple[tuple[str, str], ...]
    evidence_retention_until: datetime
    schema_version: str = DETECTION_OUTCOME_SCHEMA_VERSION
```

No validation, serialization, persistence, parsing, inference, or risk-fusion methods are public in Phase 0.
