# ShieldDome 运维与故障排查手册

## 1. 日常检查

```bash
sudo bash scripts/service-control.sh status
curl -k https://shielddome.example.internal/api/v1/health
sudo journalctl -u shielddome-api -u shielddome-worker --since today
df -h
free -m
```

关注任务积压、`degraded/failed` 数量、磁盘剩余空间和 PostgreSQL 连接情况。

## 2. 备份与恢复

```bash
sudo bash scripts/backup.sh /var/backups/shielddome
sudo bash scripts/restore.sh /var/backups/shielddome/shielddome-YYYYMMDD-HHMMSS.dump
```

恢复会停止 API 与 Worker。恢复完成后检查健康接口、最近任务和知识数量。

## 3. 常见故障

### 数据库不可用

现象：API 启动失败，Worker 重启。检查 `systemctl status postgresql`、连接串、密码和磁盘。恢复 PostgreSQL 后重启 ShieldDome 服务。

### LLM/Embedding API 不可用

现象：任务状态为 `degraded`。检查服务器 DNS、出口、防火墙、Key 是否撤销、模型名称和 API 限额。规则检测仍可用。

### Windows 页面保存模型 Key 失败

现象：模型 API 设置页提示保存失败，日志包含 `_cffi_backend`、`DLL load failed` 或“拒绝访问”。先停止本地服务，再执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\repair-windows-permissions.ps1
powershell -ExecutionPolicy Bypass -File scripts\start-windows.ps1
```

如果页面提示模型用途错误，确认 Chat 使用 `/v1/chat/completions` 和对话生成模型，Embedding 使用 `/v1/embeddings` 和嵌入模型；不要将 `/v1/rerank` 或 Reranker 模型填入这两项。

### 任务积压

检查 Worker 日志、数据库锁和外部 API 延迟。4 GB 单机默认只运行一个 Worker 进程；不要盲目增加并发导致内存耗尽。

### 磁盘不足

停止上传入口，执行 `python scripts/cleanup.py`，检查 `/var/lib/shielddome/raw`、PostgreSQL 和日志。确认备份后再清理过期文件。

### 服务启动失败

```bash
sudo systemctl status shielddome-api shielddome-worker
sudo journalctl -u shielddome-api -n 200 --no-pager
sudo -u shielddome /opt/shielddome/.venv/bin/python /opt/shielddome/scripts/initialize.py
```

常见原因是环境文件权限、数据库连接、Python 依赖或目录写权限。

## 4. 保留期任务

每日通过 cron 或 systemd timer 执行：

```bash
cd /opt/shielddome && sudo -u shielddome .venv/bin/python scripts/cleanup.py
```

当前脚本删除过期原始 EML。数据库 180 天记录清理应在正式上线前结合审计合规策略审批后启用。
