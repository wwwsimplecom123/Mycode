# ShieldDome 系统操作手册

## 用户管理

1. 使用系统管理员账号登录，进入“用户管理”。
2. 输入用户名、显示名称、至少 12 位的初始密码，并选择系统管理员、安全分析员或审计员角色。
3. 创建后可在账号列表修改显示名称与角色，或执行停用、启用和重置密码。
4. 停用账号和重置密码会立即撤销该账号现有登录会话；系统禁止停用或降级最后一个可用管理员。

## 应用中心与浏览器插件

1. 进入“应用中心”，查看 ShieldDome 企业邮件安全探针的当前版本与 SHA-256。
2. 点击“下载最新版”，网站会根据当前部署的 `extension/` 内容动态生成 ZIP。
3. 解压 ZIP，在 Chrome 或 Edge 扩展管理页开启开发者模式，选择“加载已解压的扩展程序”并打开 `extension` 目录。
4. 首次安装会自动打开插件设置页，填写终端可访问的 ShieldDome 远程服务地址和个人插件 Token；虚拟机或员工终端不能填写 `127.0.0.1`。开发或内网测试可使用 HTTP，正式环境建议使用 HTTPS。
5. 更新时重新下载最新版、覆盖原目录，并在扩展管理页点击“重新加载”。
6. 浏览器安全机制不允许普通网站静默更新开发者模式插件；企业批量自动更新需结合 Chrome/Edge 企业策略。
7. Windows 跨设备测试可使用 `scripts\start-windows.ps1 -ListenAddress 0.0.0.0` 启动监听，并在插件中填写宿主机局域网 IP；仅限受信网络测试，正式部署使用 Nginx HTTPS 地址。
8. 管理员可在“用户管理”中签发、轮换或撤销插件 Token。插件提交的检测会进入邮件事件与首页统计，并可在审计日志追溯提交用户。

## 1. 登录与退出

打开控制台后输入部署时配置的 Bootstrap 管理员用户名和密码。登录成功后，服务端通过 `HttpOnly` Cookie 创建限时会话；刷新页面或关闭后重新打开浏览器时，会话在有效期内自动恢复。点击顶部“退出登录”会立即撤销会话。连续输入错误密码 5 次，账号锁定 15 分钟。

## 首页指标钻取

- 点击“检测总量”“高风险”“待处理任务”或“降级完成”卡片，会进入邮件事件模块并自动应用对应筛选。
- 点击风险分布中的严重、高风险、中风险或低风险标签，可查看该风险等级的事件。
- 检测趋势展示最近连续 14 天的折线图；点击任意日期的数据点，可查看当天检测事件。
- 邮件事件页面会显示当前筛选条件与结果数量，可点击“清除筛选”恢复全部事件。

## 2. EML 上传检测

1. 登录控制台并进入“EML 检测”。
2. 点击上传区域，选择不超过 50 MB 的 `.eml` 文件。
3. 系统立即显示快速规则结果，并创建异步深度任务。
4. 进入“邮件事件”，点击记录查看最终风险、认证、附件、RAG 引用和 LLM 解释。

预期结果：任务最终进入 `completed`、`degraded` 或 `failed`，不得永久停留在处理中。`degraded` 表示外部 API 不可用但基础检测已完成。

## 3. 风险结果解释

- `low`：未发现明显风险，推荐 `allow`。
- `medium`：存在可疑特征，推荐提示用户。
- `high/critical`：存在强钓鱼证据，首版仍只提示和告警。
- SPF、DKIM、DMARC 通过不代表安全；合法账号被盗或内部钓鱼仍会继续检测内容与行为。

## 4. RAG 知识导入

1. 进入“RAG 知识库”，点击“导入知识”。
2. 上传 `.eml/.txt/.md/.csv/.pdf`。
3. 通过 API 或导入表单选择知识类型：`trusted_email`、`phishing_case`、`security_rule`、`soc_review`。
4. 新知识状态为 `pending`，不参与检测。
5. 审核内容和脱敏结果后点击“发布”，状态变为 `published`。

可信模板与钓鱼案例必须准确标注。错误标注会影响风险评分。误报反馈不会自动发布为可信知识。

## 5. 反馈与 SOC 复核

在邮件事件详情中提交 `false_positive`、`confirmed_phishing` 或 `uncertain`。系统记录审计事件并标记为“需要人工知识审核”，不会自动改写规则。

## 6. 模型与密钥

系统管理员可进入“模型 API 设置”，直接配置 Chat、Embedding 地址、模型和硅基流动 API Key：

1. 在“硅基流动 API Key”输入新 Key；留空保存不会覆盖现有 Key。
2. 点击“保存模型配置”。Key 只提交给后端，使用 AES-GCM 加密保存，页面只显示掩码。
3. 点击“测试连接”，验证 Chat 与 Embedding API，并检查 Embedding 返回维度。
4. 点击“清除密钥”可删除网页保存的密钥；如果服务器环境变量仍配置 Key，服务会自动回退使用环境变量。

硅基流动推荐配置：

- Chat API 地址：`https://api.siliconflow.cn/v1/chat/completions`
- Chat 模型：选择对话生成模型，例如 `Pro/zai-org/GLM-4.7`
- Embedding API 地址：`https://api.siliconflow.cn/v1/embeddings`
- Embedding 模型：`Pro/BAAI/bge-m3`

`/v1/rerank` 和名称包含 `Reranker` 的模型用于检索结果重排序，不能作为 Chat 或 Embedding 模型使用。页面与后端都会阻止保存此类错误组合。

同一硅基流动 Key 可同时调用 Chat 与 Embedding。生产环境必须使用 HTTPS，避免 Key 在浏览器到服务器的传输过程中泄露。

也可以继续通过 `/etc/shielddome/shielddome.env` 配置 `SHIELDDOME_LLM_API_KEY`。环境变量配置不会写入数据库。

## 7. 报告导出

检测详情可通过 `GET /api/v1/analyses/{id}` 获取 JSON 报告。报告不包含 API Key，也不包含原始附件内容。
