# ShieldDome 浏览器插件安装

管理员可在 ShieldDome 控制台的“应用中心”下载网站当前部署的最新版插件 ZIP。

## Chrome / Edge 本地加载

1. 先启动 ShieldDome 服务端，并确认终端浏览器能够访问其 HTTPS 或 HTTP 域名/服务器地址。
2. Chrome 打开 `chrome://extensions`，Edge 打开 `edge://extensions`。
3. 开启右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 解压从应用中心下载的 ZIP，选择其中的 `extension` 文件夹。
6. 首次安装时插件会自动打开设置页。填写终端能够访问的 ShieldDome 远程服务地址和管理员分配的个人插件 Token 并授权连接；也可以点击工具栏中的插件图标重新打开设置页。
7. 打开 Web 邮箱的邮件详情页，插件会抓取当前邮件特征并在顶部显示检测横幅。收件箱列表页不会触发检测。

## 安全说明

- API Key 只配置在本地服务端，不写入插件。
- 每位用户使用独立的 `sdp_` 插件 Token。服务端仅保存 Token 哈希，插件检测会进入邮件事件、首页统计和审计日志，并记录提交用户。
- 插件不再默认连接 `127.0.0.1`。虚拟机或员工终端必须自行配置远程服务地址；`127.0.0.1` 仅适用于服务端与浏览器运行在同一台设备的开发测试。
- Windows 跨设备测试时，可使用 `powershell -ExecutionPolicy Bypass -File scripts\start-windows.ps1 -ListenAddress 0.0.0.0` 启动监听，再在插件中填写宿主机局域网地址。该模式仅用于受信网络测试，正式部署应通过 Nginx HTTPS 地址接入。
- 插件通过后台 Service Worker 请求 ShieldDome，避免 HTTPS 邮箱页面直接访问本地 HTTP 服务时被浏览器拦截。
- 插件不会提交邮件详情 URL 中的查询参数或令牌；消息 ID 在浏览器本地摘要后提交。
- 内容脚本仅在 manifest 列出的邮箱 HTTPS 域名运行。服务器连接权限由用户在设置页按需授权，生产部署应进一步收紧邮箱域名范围。
- Chrome/Edge 不允许普通网页静默更新开发者模式插件。企业部署可结合浏览器企业策略托管更新；未配置企业策略时，请从应用中心下载最新版覆盖安装。


## 1.8.0 多邮箱适配

| 邮箱 | 页面域名 | 采集策略 |
| --- | --- | --- |
| QQ 邮箱 / 腾讯企业邮箱 | mail.qq.com、exmail.qq.com | 独立正文容器及可读取的嵌套 iframe |
| 网易 163 / 126 / yeah / 企业邮箱 | mail.163.com、mail.126.com、mail.yeah.net、qiye.163.com | 独立正文容器及邮件正文 iframe |
| Gmail | mail.google.com | 会话中最后一封可见邮件及对应发件人 |
| Outlook | outlook.live.com、outlook.office.com、outlook.office365.com | 邮件文档容器 |
| 中通服邮箱 | webmail.chinaccs.cn | 独立正文容器 |

插件每秒检查当前详情，连续两次内容稳定后提交。切换邮件会停止旧结果展示；返回列表后移除横幅。同一次详情停留不会重复提交，重新打开邮件会重新检测。修改连接配置后会重新检测。

只提交识别出的主题、发件人、收件人（页面提供时）、正文和正文链接；不会以整个页面作为正文兜底。无主题、无发件人或空正文暂不自动提交。网页采集不包含原始邮件头、附件字节及可验证的 SPF/DKIM 信息，需要完整分析时请在网站上传原始 `.eml` 文件。

**兼容性边界：** 当前版本以模拟 DOM 页面验证，尚未在登录后的各邮箱真实账户验收。邮箱新版布局、自定义企业域名、跨域正文 iframe 可能需要补充适配；未识别页面不提交。Gmail 的会话策略不代表逐封扫描整个会话。

### 更新与验收

1. 在网站“应用中心”重新下载插件 ZIP，解压后在浏览器扩展管理页重新加载，并刷新邮箱标签页。
2. 对每个使用的邮箱检查：登录页和收件箱不提交；打开邮件出现检测横幅；正文、发件人和主题对应同一封邮件。
3. 连续切换两封邮件，确认旧结论不会显示在新邮件上；返回列表时横幅消失。
4. 检查短邮件、HTML 链接、iframe 正文、Gmail 多封展开会话；在控制台确认正文没有混入导航栏和其他邮件。
5. 确认记录的 page_url 不含查询参数或片段；收件人未提供时保持空值。

开发回归：在项目根目录执行 `npm ci --prefix tests/browser`，再执行 `node --test tests/browser/*.test.cjs`。测试依赖仅用于开发，不包含在插件下载包内。

## 1.8.1 新版 QQ 修复

新增 `wx.mail.qq.com` 精确域名权限，并按真实新版 QQ 页面结构读取主题及发件人。1.8.0 在该域名不会注入脚本，因而没有检测横幅。更新插件后需重新加载插件并刷新邮箱页面。

若浏览器设置为“仅指定网站”，更新后还需允许 `https://wx.mail.qq.com/*`。已在用户已登录的新版 QQ 邮箱验证一封邮件触发并展示深度检测结果；此验证不代表其他邮箱均已实测。
