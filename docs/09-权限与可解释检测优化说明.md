# ShieldDome 权限与可解释检测优化说明

## 1. 权限模型

系统使用权限码而不是仅依赖角色名称。管理员拥有全部权限；分析员可以提交、查看本人数据、重试和反馈；审计员拥有全局只读分析与审计权限。服务接入身份仅拥有 `analysis:create`，不再模拟管理员。

## 2. 数据范围

分析记录通过 `owner_user_id`、`organization_id`、`department_id` 和 `visibility` 保存明确归属。本人列表和仪表盘在 SQL 查询阶段过滤。旧数据库启动时自动添加字段，并从历史 `parsed_message.submitted_by` 回填拥有者；无法回填的记录标记为 `restricted`。

## 3. 证据与评分

规则先输出结构化证据，再按照证据组和检测对象去重。证据包含规则版本、基础权重、置信度、抑制系数、来源和解释。相同链接的多个同类规则只保留最高有效贡献，其他规则仍留作审计但贡献为零。

风险结果同时提供：

- `evidences`：完整专业证据；
- `group_scores`：各证据组贡献；
- `calculation.items`：普通用户可读的最多五项加减分；
- `calculation.decision_explanation`：最终分数和等级阈值说明。

展示项分数之和必须等于最终风险分。封顶或安全校准产生的变化以“系统校准”单独展示。

## 4. RAG 与模型

钓鱼案例和可信邮件分别聚合，计算结果与检索顺序无关。钓鱼案例相似度至少为 0.72、可信邮件至少为 0.82 才参与评分。两侧同时达到高置信时不直接加减分，而是标记冲突并建议人工复核。

模型原始结果保留用于审计，但在线语义证据组最多贡献 20 分，不能绕过本地规则、证据去重和等级校准。

## 5. 反馈与离线评估

分析反馈会创建独立的 `analysis_labels` 标注，初始状态为 `pending`。管理员可以确认或驳回。只有 `confirmed` 标注进入离线评估数据集；知识项仍需单独审核和发布后才会参与 RAG。

执行离线评估：

```powershell
python scripts/evaluate_detection.py
```

报告包含混淆矩阵、精确率、召回率、误报率、F1、推荐阈值和发布门槛结果。没有已确认样本时脚本返回非零状态，防止将空数据误认为评估通过。

## 6. 上线建议

新策略应依次经过离线回放、影子运行、灰度发布和正式切换。至少满足钓鱼召回率不低于旧版、误报率不高于约定门槛、RAG顺序不影响结果、计算解释与最终分数一致。
